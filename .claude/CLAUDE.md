# ProofBox

Hackathon monorepo, four contributors, `main` protected by `infra/ruleset.json` (PR required, squash only).

- pnpm workspace on Vite+ (`vp`): `apps/web` only. `vp check` owns format (oxfmt, Tailwind class sorting), lint (oxlint, type-aware) and typecheck. No ESLint, Prettier or PostCSS. Import from `vite-plus`, not `vite`.
- `apps/web` uses shadcn with Base UI (`base-nova`); add components with `pnpm dlx shadcn@latest add`, never hand-install their deps. Font is Instrument Sans, matching the logo; never Geist.
- `apps/api` is a uv project (FastAPI, Python 3.14, ruff, pyrefly, pytest), not part of the pnpm workspace. It runs on the lab VM (`just deploy-api` rsyncs it to `~/proofbox-api` there and restarts it on 127.0.0.1:8000), because only the VM has `/config` and routes to VSS, VastDB and the GPU host; it keeps VastDB tables in schema `proofbox` (never touch `vss-collection`), clips in `~/proofbox-data/packs`, and seeds `docs/demo-orders.json` on startup. `just dev` tunnels it to local :8000 over SSH (`PROOFBOX_VM` overrides the host) and the web dev server proxies `/api/*` there with the prefix stripped; `PROOFBOX_API` points the proxy elsewhere when a second worktree tunnels to another port. `ssl_verify=False` in `store.py` is deliberate: the data VIP certificate is signed by VAST's own CA. SSH goes through the 1Password agent, so a locked 1Password shows up as `Permission denied (publickey)`.
- `apps/printer` is a second uv project with the same tooling: a local FastAPI agent on :8001 (proxied as `/printer/*`) that renders box labels with Pillow and sends raw TSPL to a JADENS JD-268BT over USB (pyusb, libusb-package backend). It runs on the machine the printer is plugged into; the API never imports it. Every print uses one physical label, so never call `POST /labels` without an explicit "print" from the user; use `POST /labels/preview` to check a layout. Never detach kernel drivers or use sudo for USB.
- `apps/vision` is a third uv project, the local agent on :8002 (proxied as `/vision/*`, WebSocket `/vision/ws`) that runs Ultralytics YOLOE-26s on MPS with ByteTrack. Text messages set the prompt classes, binary messages are JPEG frames, replies carry boxes normalized to 0..1. `clip` and `lap` are declared because Ultralytics otherwise pip-installs them at runtime, which fails in a uv venv. Weights and `mobileclip2_b.ts` download into `apps/vision` on first start and are gitignored. CI only runs ruff on it, since syncing pulls CUDA torch on Linux. `proofbox-replay` (`just replay <clip> <order> [render]`) shares the station's `detect` to track a recorded clip frame by frame, then opens and seals a pack through the API, so a pre-recorded clip becomes the same evidence as a live pack.
- `apps/web` signs in with `@workos-inc/authkit-react` (WorkOS project `proofbox`: Staging on `localhost:5173` and `localhost:5174` (a second worktree's dev server), Production on the Worker; client IDs in `src/main.tsx`, no API key, `devMode` on because workers.dev cannot host a custom auth domain). Each origin must be a redirect URI, CORS origin and logout URI of its WorkOS environment; change them through the WorkOS MCP.
- `apps/web/wrangler.jsonc` deploys the build as the Worker `proofbox` at `https://proofbox.luis-markmann.workers.dev` via `vp run web#deploy` (never `pnpm deploy`, a pnpm builtin). Its script `apps/web/worker/index.ts` runs first only for `/api/*` and forwards the four public reads allowlisted in `worker/public-api.ts` (order, pack video, track, summary) to the `API_ORIGIN` secret, the API's tunnel URL; every other `/api` path answers 404, so never widen the allowlist to a write. The station builds with `VITE_PROOF_ORIGIN` set to the Worker so label QR codes open there. CI runs `wrangler deploy --dry-run` on every PR, and its `deploy` job (GitHub environment `production`, secret `CLOUDFLARE_API_TOKEN`) deploys every push to `main` after `linux` passes. A manual deploy needs an explicit ask.
- `docs/vast/`, `.claude/skills/` and `.cursor/rules/vast-builders.mdc` (symlinked as `.claude/rules/vast-builders.md`) are copied from the VAST organizers' repo; `docs/vast/README.md` says how. The root `.gitignore` re-includes `.claude/`, which is ignored globally, except `worktrees/` and `settings.local.json`. Keep the copies byte-identical: they are excluded from `vp fmt` and the whitespace hooks.
- `docs/assets/build_logo.py` generates the logo; `just logo` rebuilds and copies it into `apps/web/public` and the wordmark into `apps/printer/src/proofbox_printer`. Do not hand-edit the SVGs.
- `just setup | dev | deploy-api | check | logo | replay` are the entry points.

## Versioning, CI, hooks

- One version for everything. `apps/web/package.json` is the source; Changesets bumps it. `scripts/sync-version.mjs` mirrors it into the `pyproject.toml` of `apps/api`, `apps/printer` and `apps/vision` (and their `uv.lock` via `release:version`); CI and `just check` fail on drift. The Python apps read it at runtime through `importlib.metadata`. Never edit a version by hand.
- Record a change with `pnpm changeset` (package `web`, the bump) and commit the file with the code. Never run `changeset version` locally.
- `.github/workflows/release.yml` opens and auto-merges the "chore: release" PR, then tags `vX.Y.Z` and creates the GitHub release itself; Changesets' own `web@X.Y.Z` tags are not used. It needs the lmarkmann-release App installed on the repo plus `RELEASE_APP_CLIENT_ID` / `RELEASE_APP_PRIVATE_KEY`.
- `ci.yml` has two jobs: `linux`, the required check, and `deploy`, which runs only on pushes to `main`. Every `uses:` is SHA-pinned with its tag comment; Dependabot bumps them weekly.
- prek runs from `prek.toml`: fast format and lint hooks on commit and `just check` on push. `prek install --prepare-hooks` after cloning. Ruff hooks are scoped to `apps/api`, `apps/printer` and `apps/vision`; `docs/assets/build_logo.py` is left as written.
